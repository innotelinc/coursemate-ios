CourseMate for iOS — every screen, one broadcast.

iOS will not let an app read another app's screen. A broadcast extension will: start it once and it keeps receiving frames and audio while you use your course in any other app. The answer arrives on the Lock Screen, tappable through to the full card.

View on GitHub Release notes

iOS forbids reading another app's screen

A ReplayKit broadcast extension is the one supported route, and it keeps running while the course app is in front.

A frame a second would drown the server

A perceptual hash skips unchanged screens; only a real change is uploaded, at most every 2.5 seconds.

The answer arrives behind the course app

A Live Activity puts it in the Dynamic Island and on the Lock Screen, and the tap opens that exact answer.

What it does

Capture

Frames throttled and hashed, audio chunked to 16-bit mono WAV.

Live Activity

One card per session, updated in place, never stacked.

Review

Every decision graded from the phone; a correction becomes a lesson.

Release

A tag builds, signs and uploads to TestFlight from CI.

Quick start

1 python3 tools/gen-project.py
# the project is generated
2 open CourseMate.xcodeproj
# then ⌘R on a device
3 git tag v1.0.0 && git push origin v1.0.0
# TestFlight, via the App Store Connect key

Push needs an APNs key and the Push Notifications capability; an App Store Connect key signs releases and cannot deliver a notification. That distinction is in docs/release.md.
